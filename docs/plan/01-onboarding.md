# План 01 — Онбординг-курс (7 шагов)

Статус: 🚧 **реализуется в текущем спринте** (параллельной задачей; этот документ —
спецификация-контракт, код онбординга пишется по ней).

Цель: новый пользователь за 5–10 минут проходит путь
«что это → сценарии → импорт → AI → телефон → запись → финал» и не бросает
продукт на этапе «не понял, что делать». Продвинутый пользователь не видит
курс вообще (или закрывает его за один клик).

---

## 1. Требования пользователя

| ID | Требование | Как выполняется |
|---|---|---|
| ONB-1 | Обязательная фиксация «прошёл / не прошёл» | Статус персистится: до появления аккаунтов — `localStorage`, после — `OnboardingProfile` в БД (см. §6) |
| ONB-2 | Возможность пропустить курс | Кнопка «Пропустить» в шапке каждого шага и отдельная на первом экране; пропуск тоже фиксируется |
| ONB-3 | Курс навсегда остаётся доступен | Кнопка «Обучение» в Help-центре («?» в шапке) перезапускает курс в любой момент, с любого шага |
| ONB-4 | Курс не мешает работе | Автозапуск только при первом визите; редактор за ним кликабелен; закрытие по Esc не считается ни прохождением, ни пропуском |

## 2. Состав курса — 7 шагов

Курс — последовательность карточек (Dialog/Popover поверх реального UI).
Максимальная длительность шага ~60 секунд чтения. Прогресс — точки в шапке
курса (7 шт., заполненные = пройденные).

| № | Шаг | Заголовок | Содержание | Подсветка в UI | Действие «Попробовать» |
|---|-----|-----------|------------|----------------|------------------------|
| 1 | Приветствие | «Что такое Prompter Studio» | Редактор сценария на компьютере + суфлёр на телефоне в одной Wi-Fi сети. Текст остаётся на вашей машине. 2–3 скриншота в мини-карусели | — | «Начать обучение» / «Пропустить курс» |
| 2 | Сценарии и секции | «Сценарий = секции» | Слева список сценариев, секции — смысловые блоки (тезис, демо, переход). Цвет секции = маркер в суфлёре. Хронометраж по WPM | Сайдбар сценариев + первая секция | Создать тестовый сценарий (один клик, кнопка в тултипе) |
| 3 | Импорт текста | «Перетащите .txt/.md» | Вставка из буфера, выбор файла, drag-and-drop на область секций (5 МБ, `.txt/.md`); разметка `##` = заголовок секции; предпросмотр «будет создано N секций» | Зона секций (оверлей «Отпустите файл») | Открыть диалог импорта с демо-текстом |
| 4 | AI-помощник | «Улучшить и разбить текст» | BYOK: свои ключи OpenAI/Claude или встроенный провайдер. Режимы улучшения, разбиение секции на подсекции, вид «до/после» с подсветкой diff и откатом | Кнопка ✦ в шапке и меню секции | Прогнать демо-текст через «Улучшить» встроенным провайдером |
| 5 | Подключение телефона | «QR-код и APK» | Тот же Wi-Fi; «Подключить телефон» → QR; APK-версия суфлёра по ссылке из диалога; телефон хранит офлайн-копию сценария | Кнопка «Подключить телефон» в шапке | Открыть диалог подключения (QR) |
| 6 | Суфлёр и запись | «Читайте и снимайте» | Скорость прокрутки (WPM), рестарт секции, метки дублей на телефоне, оценка дубля; **видео остаётся на телефоне** — на сервер не уходит | Статус подключения + мокап экрана суфлёра | (десктоп) показать шпаргалку жестов суфлёра |
| 7 | Финал | «Готово!» | Тёмная тема (Sun/Moon в шапке), Help-центр «?» — здесь всегда доступен повторный запуск курса; PIN-защита для публичных Wi-Fi | Тумблер темы + иконка «?» | «Завершить» |

Замечания по контенту: формулировки на русском, без жаргона; каждый шаг —
1 абзац + 3–5 пунктов; ссылки на соответствующие разделы Help-центра.

## 3. UX-принципы

1. **Не блокирует работу.** Оверлей полупрозрачный, клики по редактору
   работают; курс можно свернуть («Позже» = `lastStep` сохраняется, курс
   вернётся при следующем визите, не сразу).
2. **Автозапуск только на первом визите** — по отсутствию записи
   `ps.onboarding` в localStorage (см. §5). Повторные визиты курс не тревожат.
3. **«Пропустить» доступен на каждом шаге** — фиксированная кнопка в шапке
   диалога (не только на первом экране). Пропуск фиксируется отдельно от
   прохождения (поле `skippedAt`).
4. **Прогресс-точки** (7) в шапке; клик по пройденной точке — вернуться на шаг
   (навигация только назад по пройденным).
5. **Keyboard-доступность:** фокус в диалоге зациклен (focus trap),
   `Enter`/`→` = далее, `←` = назад, `Esc` = «Позже» (не выход из курса
   навсегда). Все элементы — стандартные Radix-компоненты shadcn/ui
   (Dialog/Tabs/Popover), aria-атрибуты из коробки; проверка табом.
6. **Тонкая персонализация:** шаги 3–6 показывают уже знакомые элементы,
   поэтому подсказки позиционируются к реальным кнопкам текущего UI, а не
   скриншотами.
7. **Мобильный суфлёр курс не показывает** — он и есть «результат» курса;
   обучение — про десктоп-редактор.

## 4. Спека состояний

```
                 ┌──────────────────────────────────────────┐
                 │ первый визит (нет ps.onboarding)         │
                 └───────────────┬──────────────────────────┘
                                 ▼
            ┌── авто-запуск шага 1 ──┐
            ▼                        │
      [шаг 1..7] ── «Далее» ───────► │ (шаг++)
            │                        │
            ├── «Позже» (Esc) ──► lastStep=N, закрыто, вернётся
            │                        │  при следующем визите
            ├── «Пропустить» ──► skippedAt=now (курс закрыт навсегда,
            │                        │  но доступен из Help)
            └── после шага 7 «Завершить» ──► completedAt=now

   Повторный запуск из Help («Обучение»): шаг = 1, completedAt/skippedAt
   НЕ сбрасываются до повторного завершения; это «просмотр», статус
   обновляется только по факту нового завершения/пропуска.
```

## 5. Текущая реализация (до появления аккаунтов)

Хранение — **per-браузер**, ключ `localStorage`:

```jsonc
// localStorage["ps.onboarding"]
{
  "version": 1,            // версия формата/контента курса
  "startedAt": "2026-09-04T10:00:00.000Z",
  "lastStep": 3,           // последний открытый шаг (1..7)
  "completedAt": null,     // ISO-дата завершения или null
  "skippedAt": null,       // ISO-дата пропуска или null
  "updatedAt": "2026-09-04T10:02:11.000Z"
}
```

Правила:

- `completedAt !== null` → курс не автозапускается, в Help кнопка «Пройти заново».
- `skippedAt !== null` → аналогично (статистика отличает пропустивших).
- Оба `null`, а `lastStep` существует → «Позже»: автозапуск возобновляется
  со `lastStep` при следующем визите.
- Приватный режим / недоступный localStorage → курс запускается заново
  каждый визит (допустимо; деградация тихая, без ошибок в консоли).
- Увеличение `version` (существенно переработанный контент) → пользователям
  с `completedAt` показываем один раз ненавязчивый баннер в Help «Курс
  обновился — посмотреть?» (не модалка).

## 6. Миграция при появлении авторизации (M2)

Схема данных (модель уже добавляется в `prisma/schema.prisma` параллельной
задачей — план 02):

```prisma
model OnboardingProfile {
  id          String   @id @default(cuid())
  userId      String   @unique
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  startedAt   DateTime @default(now())
  completedAt DateTime?
  skippedAt   DateTime?
  lastStep    Int      @default(1)
  updatedAt   DateTime @updatedAt
}
```

Логика первого входа (после успешного OAuth):

1. Есть `OnboardingProfile` для `userId` → используем его (БД — источник истины).
2. Профиля нет, но в браузере есть валидный `ps.onboarding` → **импорт**:
   `lastStep`/`completedAt`/`skippedAt` переносятся, создаётся строка
   `OnboardingProfile`, ключ `ps.onboarding` остаётся (используется как
   офлайн-кэш, обновляется при каждом изменении статуса).
3. Правило конфликта (профиль в БД есть, localStorage новее — например,
   другой аккаунт на той же машине прошёл курс): приоритет у БД; `updatedAt`
   в localStorage новее, а профиль «пустее» → берём более продвинутый статус
   (completed > skipped > in-progress по `lastStep`).
4. Инкогнито/нет localStorage → профиль создаётся с нуля, курс показывается
   как при первом визите.
5. Анонимный (LAN без аккаунта) режим продолжает работать только на
   `ps.onboarding` — миграция повторяется при каждом «первом» входе
   (идемпотентна по правилу §6.3).

API: статус читается вместе с сессией (`GET /api/auth/session` расширить
полем `onboarding`), запись — `PUT /api/onboarding`
(`{ lastStep } | { completed: true } | { skipped: true }`).
Локальный fallback: при отсутствии сети/аккаунта пишем и в localStorage.

## 7. Порядок показа «онбординг → опрос» (связь с планом 03)

Последовательность для нового пользователя:

```
регистрация (OAuth) → онбординг-курс (если не завершён) → опрос (план 03)
```

Опрос **никогда** не показывается, пока курс не завершён/пропущен —
не более одного «прерывания» за раз.
